## [Unreleased]

- Audit #24–#26 (2026-11-19): #24 found only a contract wording drift (:104, add-mailbox test flow) — rewritten to state that the create endpoint itself verifies connectivity before saving and `POST /api/accounts/:id/test` is only for already-created accounts. #25 and #26 (user-requested final review) both came back with zero findings on both routes; audit-fix loop closed. Audit #27 (user-requested repeat final review): zero findings on both routes, third consecutive clean audit.

- Audit #23 fixes (2026-11-19): backend LOW-1 — adding the same mailbox twice concurrently no longer returns 500: the INSERT in `POST /api/accounts` and in the CSV import now catches the UNIQUE constraint and returns 409 "mailbox already added" (import: that row goes to `failed` and the batch continues); verify-all section 27 added (320/320). Doc drift D1 — contract :35 rewritten: for a single add, imapHost/smtpHost are required and do not fall back to presets (only port/encryption still do); CSV import still fills a blank host from the preset. Frontend audit #23: clean, 0 findings.

- Audit #22 fixes (2026-11-19): frontend LOW-1 — after logout + re-login the first load no longer flashes "No mail here": `resetSessionState()` now invalidates any in-flight list load and sets `loading` back to true, so the list shows "Loading..." until the first `loadMessages` completes instead of rendering the empty state while `init()` is still awaiting accounts/settings (audit #11 L12's initial-value guard only covered a fresh store, not a reused one after logout); smoke +3 (144/144, reverse-control verified 143/144 without the fix). Backend audit #22: clean, 0 findings. Audit #22 also closed the audit #21 browser-verification observations: the first-look stale row after switching views is a <30ms render tick or the async batch-delete task still running (server state at the time), both self-healing, not a defect; two copies of one mail in Trash showing as one row is the audit #19 HIGH-1 merge, by design.

- Audit #21 fixes (2026-11-19): backend LOW-1 — when a permanent delete sweeps twin copies in other folders (audit #13 L3), the swept copies' local rows are now deleted in the same step instead of lingering in the list until the next folder sync (up to ~5 min, during which opening one failed and re-deleting it 502'd); `_deleteOtherCopiesInFolder` now returns the swept UIDs alongside the twin Message-IDs and `_deleteMessage` removes the matching local rows; verify-all section 26 added (315/315). Frontend audit #21: clean, 0 findings. Audit #21 also closed the audit #20 browser-verification anomaly: the vanished sent copy was the permanent-delete sweep doing its documented job (deleting the inbox copy also sweeps the sent copy of the same Message-ID), and a late-arriving inbox copy of a permanently deleted mail being blocked by the tombstone is the intended "deleted mail never comes back" semantics.

- Audit #20 fixes (2026-11-19): backend LOW-1 — `_findUidsByFingerprint` now verifies the opened mailbox path (F2 check, same as the Message-ID lookup): a wrong-folder fingerprint hit could have made the sweep delete an unrelated mail by UID; the sweep's fingerprint call is now wrapped in its own try/catch so a throw skips only the fingerprint branch and the Message-ID targets are still deleted; verify-all section 25 added (310/310). Frontend LOW-1 — async batch-delete settlement now counts failed server-draft deletions (`pendingBatchDelete.failedDraftCount`): a failed draft is reported in the "N deleted, M failed" toast (or "Delete failed, please retry" when nothing succeeded), and deleted draft rows leave the list immediately with the total adjusted, instead of lingering until the poll finishes; smoke +3 (141/141).

- Audit #19 fixes (2026-11-19): backend HIGH-1 — same Message-ID twin copies (e.g. inbox + sent copies of a self-sent mail) can now be deleted in either order: before moving to Trash, the engine checks whether the target folder already holds the same (account_id, message_id); if so it merges instead of moving (deletes the server copy in the source folder, drops the local source row, the Trash row stands as the representative), plus a compensation path if the local UPDATE still fails, so no stale row pointing at a vanished UID is ever left; regression section added to verify-all (306/306). Backend LOW-1 — Message-ID lookup now verifies the opened mailbox path (F2 check), same as folder sync. Frontend MED-1 — batch-delete settlement now reads the `failed` field: partial failures toast "N deleted, M failed", total failure toasts "Delete failed, please retry" instead of "Moved 0 to Deleted". Frontend LOW-1 — delete/move failures map internal error text (UNIQUE constraint / SQLite internals) to a friendly "Delete failed, please retry" and "could not confirm new location" to "Delete failed: the server cannot find this mail, please refresh and retry"; other backend business errors still shown as-is. Frontend LOW-2 — change-password now blocks an empty current password client-side ("Please enter the current password."). Contract: added the four-required-fields + account-format rule for add-mailbox, the send-recipient validation rule, and the "same Message-ID copies merge into one row when moved into the same folder" note.

- User-requested validation & autofill improvements (2026-11-19): sending mail now validates recipient format before sending — recipient is required and every To/Cc address must be a valid email (full-width commas also split correctly), on both the compose window and the server, so a bad address never reaches SMTP; drafts may still hold unfinished addresses. Adding a mailbox now requires all four fields (account, password, IMAP server, SMTP server) with the account format-checked, on both the form and the server, each missing item named in its own message. Browser autofill is blocked on the change-password fields (old, new, confirm) and on the add-mailbox account/password fields — the fields stay empty until focused and typed into by hand (readonly-until-focus); the mailbox preset server fill after typing an address still works as before.

- Audit #18 fixes (2026-11-19, sixteenth pre-launch full review; frontend 1 MED, backend 1 LOW + 1 doc note, all fixed): deleting a message or moving it to spam no longer risks a stale in-flight list response bringing the row back — list mutations now invalidate pending loads (sequence bump, never an abort, which would have cleared the list and shown a load-failure toast). The delete-account path no longer removes the IMAP error listener before the logout handshake finishes, so a server that resets the connection mid-logout cannot abort the whole backend process — this was the root cause of the intermittent verify-all crash at the end of section import18b (6 new deterministic regression assertions, including a reverse check that the old code aborts). The `truncated` search flag is now documented as it actually behaves: it marks the global FTS candidate set being capped at 2000, so a scoped view can still report it when the limited result may be incomplete.

- Audit #17 fixes (2026-11-19, fifteenth pre-launch full review; frontend 1 MED + 3 LOW, backend 2 LOW + 2 doc items, all fixed): search scope is now settled — All Inboxes / All Unread keep searching the whole mailbox, while All Drafts / All Sent / All Trash / single-folder views only search that folder (before this, searching in All Drafts could surface inbox mail and deleting it from that view would delete the real inbox mail). Moving a draft to spam (or back) now removes the row from the drafts list immediately instead of leaving it until the next load. The account unread badge no longer flips between two sources — a mismatch now triggers one reconciling reload instead of a silent overwrite. On mobile, opening an account whose folders failed to load now says the load failed instead of claiming it is still syncing. The SSRF check now also blocks the uncompressed and compatibility IPv4-mapped IPv6 forms (0:0:0:0:0:ffff:7f00:1, ::7f00:1). A mail that is a single binary part (no text body at all) now gets part number 1, so its attachment downloads instead of 404ing. README no longer hard-codes the verify-all count (it drifted every round); contract now states the per-view search scope.

- Audit #16 fixes (2026-11-19, fourteenth pre-launch full review; frontend 1 MED + 4 LOW, backend 3 LOW + 3 doc items, all fixed): Sent-view dedup now has real test coverage (same-recipient pairs merge, different-recipient pairs stay, missing-recipient rows behave like the backend) and its null-value edges match the backend (missing date or size never merges). Drafts-view search now matches multi-word queries against the full draft body, not just the first 80 characters of the snippet. The new-mail badge no longer double-counts when the list already has the message. Opening a draft whose account was deleted in another tab now says so instead of opening a blank-sender compose window. SSRF check now blocks multi-segment IPv4-mapped IPv6 loopback forms (::ffff:0:7f00:0001 and friends). Attachment part numbers no longer shift when a message has a bare binary part without disposition or filename. The tracking-pixel hook now also catches opacity:.0, 1.0px and 0.0px spellings on both passes. README verification counts and file list brought up to date.

## [0.1.0] - 2026-11-17

### Added
- Single-user login: username (case-insensitive) + password, 5-failure lockout, 30-day remember-me, change username/password in Settings
- Unified inbox: all mailboxes merged by time; aggregate views for inbox, unread, drafts, sent, trash
- Real folders only: folder list synced from the IMAP server via `LIST`, never fabricated
- Known-provider presets: 163, Gmail, Outlook, QQ, iCloud and more auto-fill IMAP/SMTP on add
- Real-time push: new mail arrives over WebSocket, unread badges update instantly
